The original Probe 2 prompt was identified as potentially leading because it framed the question around necessity ("Is it strictly necessary for A to happen before B?"), which appeared to prime Mistral-7B toward answering "yes" regardless of the actual pair. Evidence for this was the LLM's near-blanket "yes" behavior under the original prompt: specificity of 0.9% combined and recall of 0.996, meaning the model predicted "necessary" for almost every pair it saw.

To test this, the prompt was reframed around flexibility instead: "Could A and B happen in either order without affecting the task, or is one order strictly required?" This flips the yes/no polarity, so p_yes now means P(flexible) rather than P(necessary). A corresponding inversion (1.0 - py) was added in score_probe2_keep in the classification notebook to keep the LLM baseline correctly oriented toward y=1 (real edge).

Running the classification notebook with only the prompt changed and without retraining the probe confirmed the leading bias: LLM specificity jumped from 0.9% to 28.0%, and LLM recall dropped from 0.996 to 0.788 — the model was now genuinely discriminating rather than defaulting. The probe collapsed (F1 0.789 → 0.516) due to the expected train/inference mismatch, since its weights were still learned from necessity-prompt hidden states.

Retraining Probe 2 on hidden states from the new flexible prompt resolved the mismatch. The retrained probe improved on every metric: combined F1 0.789 → 0.813, same-depth F1 0.826 → 0.847, cross-branch F1 0.843 → 0.864. The cross-branch condition, which previously showed the LLM "winning" (F1 0.911 vs 0.843) due to a class imbalance artifact, now correctly favors the probe (0.864 vs 0.810). The flexible prompt is a genuine improvement and the results with the retrained probe are the ones to report.
